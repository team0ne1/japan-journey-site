# 探店收藏夹

2026-09-13 · 本地实现，等待领队确认后再提交、推送和部署。

## 成员使用

「全程」下方新增「探店收藏夹」。所有已登录成员与领队均可添加、查看和导出完整收藏；收藏不会自动写入正式行程，也没有在收藏夹内添加评论。

必填字段为所属地区、地点名称、营业时间、Google 地图链接。营业时间使用“填写营业时间／待确认”单选；选择待确认会禁用输入框并自动保存“待确认”，切回填写会恢复原输入内容。可记录每周休息日、最后点单时间。新增可选的消息来源链接，可填写 Bilibili、小红书、大众点评、YouTube 等网页或分享短链接；留空可正常提交。填写后显示在卡片并纳入 CSV 导出。只保存 HTTP／HTTPS 链接，不抓取或嵌入推荐内容，旧记录默认无来源。店名保留原语言，地图链接接受 Google Maps HTTPS 地点页及常用分享短链接；服务端不请求或展开用户链接，具体地点与营业时间由添加者核对。

地区顺序为大阪、京都、宇治／城阳、奈良、神户／有马、和歌山、其他地区、待分类。每组使用白底卡片，以蓝、绿、棕色系边框区分地区，同时显示地区标题和数量；同组最新收藏排在前面。有马温泉归神户组，加太归和歌山组。旧收藏缺少地区时保留在待分类组，不丢弃数据。

导出入口下载 `trip-favorites.csv`，每个地点一条记录，列为地区、地点名称、营业时间、Google 地图链接、消息来源链接、添加者、感兴趣人数、感兴趣成员；未填写来源的单元格留空。按上述地区顺序排列，同组最新收藏在前。采用 UTF-8 BOM、CRLF 行分隔及双引号转义，保留中文、逗号、引号和多行营业时间，方便 Excel 与 AI 读取。对于以 `= + - @` 开头（包括前置空白）的文本，导出时加英文单引号防止被表格软件解释为公式；数据库原文不变。CSV 不包含卡片颜色。每次导出读取数据库当前完整快照。

首版提供新增、浏览、刷新与导出；尚未实现收藏项修改、删除或纳入正式行程操作。相同地图 URL 会提示重复；不同链接指向同一家店时尚不能自动识别。

## 实现与数据

- `src/favorites.ts`：现有 TripAuth Durable Object 内的独立 SQLite 表 `favorites` 和 `favorite_rates`。
- `src/favorite-regions.ts`：前后端共享的地区 ID、名称与顺序。
- `src/auth.ts`：验证现有30天登录态并提供服务端添加者身份。移除成员时保留收藏、匿名化添加者，同时撤销其访问。
- `src/worker.ts`：`GET /api/favorites`、`POST /api/favorites/create`、`GET /api/favorites/export`。接口及静态资源沿用登录保护；写入沿用来源校验和请求长度上限，响应禁止缓存。
- `web/favorites.js`、`web/favorites.css`：表单、错误保留、共享列表、地区卡片和手机布局；用户文本以 textContent 渲染。
- `dist/app.js`：`#view=favorites` 页面状态；日期入口返回原只读行程。

SQL参数绑定、同步事务、服务端生成身份、每次提交ID及唯一约束避免伪造作者和并发重复写入。每名成员10分钟最多新增30条，单趟旅行最多500条，导出不受界面显示数量影响。已有数据库仅增加新表／缺失的地区列；不新增 Cloudflare 资源、绑定、密钥或部署配置。

数据库语义参考 [Cloudflare SQLite storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)。

48 项现有与新增运行时测试通过，覆盖登录／评论回归、成员间共享、撤销权限、重复提交、恶意链接、频率限制、对象回收后持久化、完整导出、地区排序和旧记录迁移。本地 Chrome 验证了填写错误提示、成功添加、刷新、日期切换与手机无横向溢出；隔离本地数据库中的配色示例均标注“本地测试”，不属于正式收藏。

## 感兴趣表态

每张卡片有心形「感兴趣」按钮，再次点击可取消；领队与每位成员每个地点各计一次，添加地点不自动表态。按钮仅显示粉红心形图标、背景为白色；后方直接展示胶囊型用户名标签，完整显示姓名、不截断，空间不足时换行，人数靠右显示，所有已登录成员可见。保留地区分组及组内时间排序，不按人数自动调整位置；正式行程不受影响。CSV 同步导出人数与成员名单，无人表态时为 0 和空白。其他成员的最新表态在打开收藏夹或刷新列表时读取。

`POST /api/favorites/interest` 接收 `favoriteId` 和布尔 `interested`，由服务端登录态确定成员身份。使用现有 SQLite 新表 `favorite_interests`，以地点与成员为联合主键；明确设置状态避免重复提交多计或意外取消。移除成员同时删除其表态。写入沿用来源验证，接口不需要额外 Cloudflare 配置。测试覆盖并发表态去重、取消、跨成员可见、持久化、身份与来源验证、CSV 和成员移除。

地区边框色（白色卡片背景，每区独立）：大阪 `#3478B8`、京都 `#698B43`、宇治／城阳 `#23836A`、奈良 `#A77536`、神户／有马 `#646BA3`、和歌山 `#398F9C`、其他地区 `#A65F4D`、待分类 `#77716A`。
