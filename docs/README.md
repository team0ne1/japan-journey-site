示例使用拟议的 `1.0-draft` 格式，不是已生效的生产数据源。路线内容沿用现有网站；2026-09-12已补查收费景点和体验的成人票价及来源，开放时间、天气、实际班次未在此轮重新全面核查。62条地点资料中包括一个尚未指定精确坐标的鸭川备选范围；共有86个行程节点、163个时间色块及37项费用条目（茶体验与花火分别列项，未预订餐饮预留已移除）及12条成人票种记录。现有节点编号全部保留。

已对示例做数据核对：与原代码逐项比较路线、酒店、游览时长、开放信息、预算及时间分配，并检查方案／跨日引用、时间顺序和协作字段排除。随后加入成人票价引用，票价引入时主线每日预算金额保持一致；随后按照“只计已预订餐厅”移除餐饮预留并重算合计，详见票价核对文档的范围说明。该核对只验证文档迁移内容，不表示拟议解析器或合并功能已经实现。

已确定的边界：

- 每份行程 Markdown 只包含行程信息，不包含评论、身份、个人副本归属、审批或版本历史。
- 当前行程界面只读，成员通过已有评论提建议。个人副本编辑与提交合并保留为未来设计，本阶段不启用。
- 所有成员只能在领队当前正式行程上发表评论，评论对所有已登录同行成员可见。
- 个人副本、待审提案及差异预览均不开放评论；正式行程中的 Plan B 仍属于领队行程。
- 餐饮只计算已预订餐厅，记录对应餐段Tabelog人均参考或已订套餐价；未预订餐饮不计入每日合计。
- “正式行程”表示领队当前发布版本，不表示酒店、餐厅和活动已经预订。

建议先阅读工程方案的“决策摘要”和“合并规则”，再查看语言规范与示例。本目录没有解析器、数据库迁移或任何运行时代码。

餐饮信息来源核查：已查看[Tabelog繁体入口](https://tabelog.com/tw/)及[一份店铺详情页](https://tabelog.com/tw/kyoto/A2601/A260401/26024014/)，确认其区分预算、消费统计及服务费说明。该店仅用于核对平台字段，没有加入本行程，也没有进行预订。Tabelog区间不等于实际账单；餐厅确定且预订成功后逐店查询。

本地验证：`npm run check` 通过（33项登录与评论测试）；实际 Chrome 检查桌面与390px手机布局、地图／卡片跳转、照片放大和评论提交。另核对86个稳定评论节点、37项费用以及9个日程版本总额。正式网站仍为之前的发布版本。
