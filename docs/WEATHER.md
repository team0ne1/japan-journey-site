# 每日天气模块

核查日期：2026-09-13。开发目录：`/Users/team0ne_m/Code/japan_journey_site/kansai-cloudflare-source`。

本功能在 Day 0 展示日本当前日期的当前天气、逐小时预报和日出日落；在每一天行程中展示对应旅行日的逐小时天气和日出日落。不会调整时间轴、正式行程、费用、评论、收藏夹或预约。本轮完成本地开发及验证，未提交、推送或部署。

## 数据源与使用许可

使用 **Open-Meteo Weather Forecast API** 的官方 HTTPS 接口：

`GET https://api.open-meteo.com/v1/forecast`

不直接抓取日本气象厅网站，不使用第三方网页爬取或付费绕过接口，不购买服务、不申请 API Key。使用通用接口的默认模型选择，不能将显示结果宣传为“日本气象厅官方发布的地点预报”。

依据当前项目是私人旅行成员使用、无广告和收费订阅的非商业用途，本次接入符合 Open-Meteo 免费服务的用途条件。免费托管服务许可和天气数据许可是两个不同层次：

16天请求超过两周，供应商可能按多于1个计费调用单位计算，不能直接把 HTTP 请求数等同于额度单位。缓存各 Cloudflare 边缘机房独立且可能被驱逐；本功能没有新增跨机房全局额度计数器，不能把缓存视为强制配额保障。当前私人小规模使用按需查询；扩展到大量用户或商业用途时，应重新核算供应商调用单位及适用方案。

查询时仅发送地点经纬度、预报字段、时区和预报长度；不转发 Cookie、成员姓名、评论、收藏或用户浏览器 IP。供应商可看到服务端出口 IP，且其隐私条款说明日志可能包含查询坐标。这些是行程预置地点，不获取设备实时定位。

## 实现及接口

- `dist/weather-config.js`：旅行年份、每天及 Plan B 的天气地区；坐标继续来自 `dist/data.js` 的 PLACES。
- `scripts/build.mjs`：在现有构建中校验日期／地点并生成 `src/weather-days.ts`；不手工编辑生成文件。
- `src/weather.ts`：固定上游地址、JSON 校验、Japan 日期边界、缓存和失败降级。
- `src/worker.ts`：`/api/weather` 沿用 session 和域名校验；不通过认证不发上游请求。
- `dist/weather.js` / `dist/weather.css`：独立展示组件及样式。CSS 没有修改 `dist/itinerary-ui.css`；用户已有修改保留。
- `tests/weather.test.js`：8项天气及访问边界测试。

接口：`GET /api/weather?day=1&plan=A&location=osaka`。

`day` 必须是行程1–7；`plan` 默认A，可为B；`location` 默认该天第一个天气地区，必须属于该天方案白名单。地点来源于预先配置的城市／景区代表位置；不是所有景点的入口级预报，也不自动跟随行程节点时段切换。未知日期、方案或地点返回400，未登录401，非GET为405，服务失败503并返回 `Retry-After: 60`。所有 HTTP 响应沿用 private/no-store 与现有 CSP；不会放宽浏览器 connect-src。

成功返回包含：`status:ok`、`date`、`location:{id,name}`、`timezone:Asia/Tokyo`、`sunrise`、`sunset`、`fetchedAt`、`stale` 以及24条 `hours`。每条包含 `time`、`temperature`、`precipitationProbability`、`code`、`isDay`。预报和日出日落时间为日本当地ISO时间；`fetchedAt` 为UTC ISO时间，界面按日本时间显示。

上游固定字段：

- `current=temperature_2m,weather_code,is_day`
- `hourly=temperature_2m,precipitation_probability,weather_code,is_day`
- `daily=sunrise,sunset`
- `timezone=Asia/Tokyo&forecast_days=16&temperature_unit=celsius`

单位、时区、24小时结构通过校验后才缓存。0°C、0%是有效值；null显示“—”，不会改成晴天或零降雨。气温四舍五入为整数，天气代码转换为中文及Unicode天气符号，日出日落保持分钟值。

## 缓存和页面状态

按地点坐标与日本当前日期共享 Workers Cache API 缓存；没有新增 KV、D1、DO 类、表、密钥或绑定。一次请求取该地点未来16天，缓存1小时。供应商8秒超时，响应最大256KB，拒绝重定向；出错保留最近6小时内数据并标注旧数据，超过时限返回失败。失败标记在边缘缓存保留60秒，避免连续重试打上游。边缘缓存只包含公开气象数据及获取时间。

浏览器正常天气缓存以服务端获取时间计算1小时，避免叠加缓存期限；无预报状态从收到响应起缓存1小时。旧预报降级状态只缓存1分钟且不超过原数据6小时期限，跨日本日期失效；不使用localStorage、不做后台轮询。浏览器请求最多等待12秒；取消旧请求、用版本号防止迟到响应覆盖新日期或地点。进入收藏夹或全程页时取消天气加载；不会请求所有地区来预热缓存。

默认从07:00附近展开天气条，可横向滚动查看00:00–23:00。天气地点使用横向卡片轮播：触摸设备左右滑动天气卡片，桌面端也可使用前后按钮或分页圆点；滑到地点后才按需查询，并在本次页面会话内保留所选地区。卡片内小时天气条保持独立横向滚动。页面显示“数据获取于”，它不是模型发布时间，也不表示实况天气。

预报范围为日本当天起16个日历日（当天至第15天之后）。未来更远日期返回 `outside_forecast`，过去日期返回 `past`，这两类状态不请求供应商。**本阶段日出日落随同预报获取，预报期外也暂不显示；未加入额外天文API或本地天文算法。** 无预报时明确提示，不用示例数据或气候平均值补充。
